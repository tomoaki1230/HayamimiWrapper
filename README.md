# HayamimiWrapper

オープンソースの音声認識エンジン [hayamimi](https://github.com/oboroge0/hayamimi) を、かんたんに使えるようにした Windows 用の文字起こしアプリです（実行ファイル名: HayamimiWrapper.exe）。

![リアルタイム文字起こし画面](docs/images/live.png)

*リアルタイム文字起こしの画面（表示している発言は説明用の例です）*

## 主な機能

- **ボタン 1 つで導入**: Python や ffmpeg を事前にインストールする必要はありません。モデルは「標準（日本語・英語、約 1.1GB）」と「フル機能（多言語・話者の区別・英訳、約 3.1GB）」から選べます
- **リアルタイム文字起こし**: マイク / PC の音（スピーカーループバック）をそれぞれ ON/OFF。モデルを先に読み込んでおけば「● 開始」ですぐ始まります
- **速報と清書**: 話し終えるとすぐ出る「速報」と、前後をまとめて認識し直した「清書（高精度）」の 2 段階。話している間は「聞き取り中」の文字も表示します
- **取りこぼし対策**: 長い発言は文の切れ目で分けて認識し、清書で抜けた文は速報の文で補います。大きな声の直後の小さな声も検出できるよう、発話検出をリセットします（詳しくは「[認識率を上げるための独自の処理](#認識率を上げるための独自の処理)」）
- **会話の種類（認識プロファイル）**: 場面に合わせて選ぶと、認識の設定がまとめて切り替わります。各値を自由に変えるカスタム設定も可能
- **話者の区別**（フル機能のモデル）: 話者ごとに S1・S2… のラベルと薄い背景色。参加人数を指定すると精度が上がります
- **設定の即時反映**: モデルを読み込んだままでも、会話の種類・言語・置換辞書などの変更がすぐ反映されます
- **時刻つき・保存**: 各行に時刻（リアルタイムは実時刻、ファイルは経過時間）。コピー、txt / md での保存、フォルダへの自動保存
- **ファイル文字起こし**: mp3・m4a・wav・mp4 などをドラッグ＆ドロップ
- **オフライン処理**: 音声は PC の中だけで処理（インターネットに送らない・GPU 不要）
- **既存の環境に影響しない**: 変更はアプリ専用の保存場所の中だけ（PATH・レジストリ・ほかの Python 環境に触れない）
- **プロキシ対応**: OS のプロキシ設定・手動指定・認証付きプロキシでセットアップ可能
- **バージョン固定**: hayamimi は動作確認済みのバージョンを使用（勝手に最新版へ更新しない）

## 動作環境

- Windows 10 / 11（64 ビット）
- 空き容量 2〜5GB（モデルの種類による）
- 初回のセットアップ時のみインターネット接続

## ご利用の前に

配布しているアプリ（exe）はデジタル署名をしていません。そのため、ダウンロードや初回の起動時に、Windows（SmartScreen）やウイルス対策ソフトの警告が表示される場合があります。

SmartScreen の警告が出た場合は、「詳細情報」→「実行」で起動できます。

### スマート アプリ コントロールについて

Windows 11 の「スマート アプリ コントロール」がオンになっている PC では、署名をしていないため、アプリの実行がブロックされる場合があります（ブロックされたときは、画面が表示されずに終了することがあります）。公開前に、スマート アプリ コントロールがオンの Windows 11 で起動できることを確認していますが、ブロックされるかどうかは Microsoft の判定によるため、必ず起動できるとは限りません。

ブロックされた場合、このアプリだけを許可する方法はありません。**解決策は、スマート アプリ コントロールをオフにすることのみです**（「Windows セキュリティ」→「アプリとブラウザーの制御」→「スマート アプリ コントロールの設定」）。

なお、最新の Windows Update を適用していれば、オフにした後も「Windows セキュリティ」から再びオンにできます。オフにするかどうかは、ご自身の判断でお願いします。

## 使い方

1. `HayamimiWrapper-Setup-<バージョン>.exe` でインストールします（または `HayamimiWrapper-<バージョン>-portable.exe` をそのまま実行）
2. アプリを起動し、「セットアップ」画面で **セットアップを開始** を押します（初回のみ・10〜30 分）
3. 「リアルタイム」画面で **モデルを読み込む** → 読み込みが終わったら **● 開始**。ファイルの場合は「ファイルから」画面にファイルをドロップします

会社のネットワークなどでプロキシが必要な場合は、セットアップの前に「ネットワーク」画面でプロキシを設定してください。
詳しい使い方は、アプリの「使い方」画面を参照してください。

## 認識率を上げるための独自の処理

hayamimi 本体には手を加えず、アプリ側で次の処理を追加しています。どれも公開されている日本語音声データ（FLEURS・ReazonSpeech・Common Voice など）で効果を確かめたうえで採用し、既定で有効になっています。

### 抜け落ちを防ぐ処理

音声認識モデルは 1 文ずつの音声で学習されているため、複数の文を含む長いまとまりを一度に認識すると、一部の文が出てこないことがあります。会話で間を空けずに話し続けたときや、BGM・笑い声などで無音が少ない音声（PC の音で動画や配信を文字起こしする場合など）で起こりやすくなります。

- **長い発言の分割認識**: 長くなった発言のまとまりは、中を細かく調べて文の切れ目（短い間）で分け、1 文ずつに近い単位で認識します。特に長いまとまりは、まとめて認識すると大半の文が落ちやすいため、分けた単位だけで認識します
- **速報の抜けの再認識**: 話している間に表示した「聞き取り中」の文字が速報に含まれていない場合は、文が落ちたとみなし、まとまりを分けて認識し直します。良くなったときだけ採用します
- **清書の補完**: 清書は複数の速報をまとめて認識し直すため、文が落ちることがあります。清書が元の速報より大幅に短いとき（文が落ちたとき）は速報の文を使い、先頭や末尾の文がまるごと抜けたときは速報の文で補います

### 聞き取りにくい声への処理

- **発話検出のリセット**: 大きな声の直後に続く小さな声は、発話として検出されにくくなります。発言の後に短い無音が続いたら発話検出の状態をリセットし、声の小さい参加者の発言を取りこぼしにくくしています
- **会話の種類（認識プロファイル）**: 発言の区切り方（区切りとみなす無音の長さ・1 発言の最大の長さなど）を、場面ごとに評価して決めた値に切り替えます。どの評価データでも悪化しない値だけを採用しています

### 話者の区別の精度（フル機能のモデル）

- **参加人数の指定**: 指定した人数に達するまでは声の似た人も別の話者として分けやすくし、達した後は既存の話者に当てはめやすくします。途中で加わった人は 1 人まで新しい話者として認め、それを超えて話者が増え続けないようにしています（PC の音では、BGM や効果音で声の特徴がぶれて、同じ人が別の話者として増えやすいため）
- **結果のクリアで番号を振り直す**: 結果をクリアすると、話者の番号が S1 から振り直されます

### 音声を取りこぼさないための処理

音声認識エンジンは認識を 1 本の流れで順に行うため、長い発言を認識している間は次の音声に進めません。その間に届いた音声を失わないよう、次の処理を加えています。

- **取り込みのバッファの拡張**: マイクと PC の音を両方使うときの音声のたまり場所を約 2 秒分から約 10 秒分に広げ、認識が追いつくまで音声を捨てずにためておきます
- **PC の音の取り込みの安定化**: PC の音の取り込みのバッファを広げ、取り込みの処理を Windows の音声用の優先実行に登録して、CPU が混んでいても音が途切れにくくしています

## 開発

必要なもの: Node.js 22 以上（動作確認は 24）。`npm test` のラッパーの結合テストには Python 3 を使います（無ければその部分のテストは飛ばされます）。

```bash
npm install
npm start          # アプリを起動
npm test           # テスト
npm run check      # 構文チェック
npm run build      # 構文チェック → Windows 版の展開済みアプリを生成（dist/win-unpacked/）
npm run dist       # 構文チェック → Windows 用インストーラー exe と portable exe を生成（dist/）
npm run icon       # アイコン（src/renderer/icon.svg）から build/icon.png を生成
```

- `npm run build` / `npm run dist` は、Windows 用の ffmpeg.exe をダウンロードしてから（`npm run prepare:win`）ビルドするため、インターネット接続が必要です。Linux / WSL でビルドする場合は Wine も必要です。
- 環境変数 `ELECTRON_RUN_AS_NODE` が設定されているシェル（一部のエディターの拡張機能から起動したシェルなど）では、`npm start` と `npm run icon` が起動しません。その場合は `env -u ELECTRON_RUN_AS_NODE npm start` のように外して実行してください。
- hayamimi 本体とモデルはアプリには含まれず、セットアップ時にダウンロードされます。
